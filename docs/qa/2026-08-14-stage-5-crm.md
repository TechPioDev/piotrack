## Architecture delivered

- **Entities** (all tenant-scoped via `BelongsToTenant`): `companies`, `contacts`, `leads`,
  `pipelines`, `pipeline_stages`, `deals`, `activities` (polymorphic), `saved_views`, `import_jobs`.
  Money in minor units; attribution fields on contacts/leads/deals feed the future attribution chain.
- **RBAC**: 18 `crm.*` permissions (`{contact,company,lead,deal}.{read,create,update,delete}`,
  `activity.manage`, `import`) wired into the role map; every CRM route is `can:`-gated and behind
  the `crm` plan feature (`entitlement:crm`).
- **Provisioning**: each organization gets a default "Sales Pipeline" (New → Qualified → Proposal →
  Negotiation → Won → Lost) on creation.
- **Services**: `CrmProvisioner`, `LeadConversionService` (dedupes company by name and contact by
  email), `ContactImporter` (header aliasing, validation, duplicate detection, preview, commit +
  history). Search extended with contacts/companies/deals.
- **Morph map**: stable polymorphic aliases (`contact`/`company`/`lead`/`deal`) via a `HasActivities`
  contract implemented by the four subject models.
- **UI**: sidebar CRM group; contacts/companies/leads index tables with search + create dialogs;
  contact & company detail with related records; a shared activity timeline; a deals kanban board
  with per-card stage changes; lead conversion dialog; and a contacts import wizard (upload → preview
  → confirm) with history.

## Defects discovered & fixed

- Polymorphic activity subjects needed a shared contract — introduced `HasActivities` implemented by
  Contact/Company/Lead/Deal so `resolveSubject()->activities()` type-checks.
- `ContactImporter` duplicate map used a Collection with unstable generics → switched to a plain
  `array<string,bool>`.
- Import preview redirect reset the selected file → added `preserveState` so the commit step keeps it.
- A CRM entitlement test wrongly assumed the free tier lacks `crm`; corrected — `crm` is a baseline
  feature every plan (and the free fallback) grants.
