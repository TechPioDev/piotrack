## Manual QA (browser, http://localhost:8734)

- Register → email verification (via mail log link) → dashboard. Unverified users are redirected to
  the verification notice; verified users reach the dashboard.
- Enrolled in 2FA: QR + manual secret shown, confirmed with a live authenticator code, 8 recovery
  codes issued. Logged out, logged back in → redirected to challenge → completed with TOTP → dashboard.
- Created an API token (plaintext shown once), authenticated `GET /api/user` with it, revoked it via
  the confirmation dialog → subsequent API call returns 401; token count 0.
- Audit trail verified: exactly one row per event; failed-login context stores the email, never the
  password. Recovery-code and 2FA/token events recorded.
- Responsive: settings pages checked at mobile width (375px) — no horizontal overflow.

## Security checks

- Backend authorization/enforcement: `verified` on app routes; `password.confirm` on all credential
  management; ownership scoping on token revoke (cross-user → 404).
- Secrets: 2FA secret + recovery codes stored `encrypted`/`encrypted:array`; API tokens hashed
  (plaintext shown once). `SESSION_SECURE_COOKIE` documented for production.
- Throttling on login (5/min lockout), register, forgot/reset, 2FA confirm and challenge.
- Audit context contains no passwords/secrets (asserted in tests).

## Defects discovered & fixed

1. **Double audit logging** — `RecordAuthEvents` was both auto-discovered by Laravel _and_ manually
   registered via `Event::subscribe`, recording every auth event twice. Removed the manual
   subscription and the `subscribe()` method; added regression assertions that exactly one row is
   written per login/logout/registration. (Found in manual QA, confirmed via audit-table inspection.)
2. Starter-kit TypeScript form types and one blend-mode value adjusted (carried from Stage 0 kit);
   sidebar rebranded "Laravel Starter Kit" → "Piotrack".
